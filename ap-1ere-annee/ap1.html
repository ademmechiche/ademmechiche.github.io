AP 1 – Serveur de fichiers Samba

Mise en place complète d’un serveur de fichiers Samba sous Debian permettant le partage sécurisé de répertoires pour différents utilisateurs et groupes.

Contexte

Dans le cadre du module Système du BTS SIO SISR, nous avons dû installer et configurer un serveur de fichiers Samba sous GNU/Debian. L’objectif était de permettre à des utilisateurs Windows et Linux d’accéder à des répertoires partagés avec des droits différents selon leur groupe.

Le serveur devait être intégré dans un réseau local en 172.30.1XX.0/24 avec :

  • un serveur Debian (Samba),
  • un client Windows,
  • un client Debian/Ubuntu,
  • des utilisateurs répartis dans deux groupes : gpb1sio1 et gpb1sio2.

Besoin

L’entreprise fictive souhaite mettre en place un serveur de fichiers centralisé permettant :

  • un répertoire personnel pour chaque utilisateur,
  • un répertoire partagé commun (B1Sio),
  • deux sous-répertoires avec droits différents (B1Sio1 et B1Sio2),
  • un accès depuis Windows et Linux,
  • un partage “PartagePourTous” accessible en écriture,
  • un partage “Depot” accessible uniquement en écriture (pas de modification).

Environnement

Système : Debian 13 (Trixie)
Service : Samba 4
Clients : Windows 11 + Debian
Outils : SSH, nano, smb.conf, testparm, chmod, chown

Réalisation

1. Installation de Samba

Installation du paquet Samba via apt, puis vérification du service. Le fichier /etc/samba/smb.conf a été utilisé pour configurer les partages.

2. Création des groupes et utilisateurs

Deux groupes ont été créés : gpb1sio1 et gpb1sio2. Les utilisateurs suivants ont été ajoutés :

  • alicia (gpb1sio1)
  • nabil (gpb1sio1)
  • clara (gpb1sio2)
  • hedi (gpb1sio2)

3. Mise en place des répertoires

L’arborescence suivante a été créée dans /home :

  • B1Sio/
  • B1Sio1/
  • B1Sio2/

Les groupes propriétaires ont été attribués avec chown.

4. Configuration des droits Linux

Les droits des répertoires personnels ont été modifiés pour respecter les règles suivantes :

  • propriétaire : lecture, écriture, exécution,
  • groupe : lecture + exécution,
  • autres : aucun accès.

Les répertoires B1Sio1 et B1Sio2 ont été configurés pour que chaque groupe ait :

  • lecture/écriture dans son répertoire,
  • lecture seule dans l’autre.

5. Configuration des partages Samba

Exemple de partage configuré dans smb.conf : 

[partageb1sio]
comment = Dossier partage pour les B1
path = /home/B1Sio
browsable = yes
writeable = yes
create mask = 0755

6. Tests d’accès

Les tests ont été réalisés depuis :

  • Windows : via \\PartageSMB et montage de lecteur réseau,
  • Linux : via smb://PartageSMB.

Les droits ont été validés : - Alicia peut écrire dans B1Sio1 mais pas dans B1Sio2. - Clara peut écrire dans B1Sio2 mais pas dans B1Sio1.

7. Partages supplémentaires

Deux partages supplémentaires ont été créés :

  • PartagePourTous : écriture et modification pour tous les utilisateurs,
  • Depot : écriture uniquement (pas de modification possible).

Bilan

Ce TP m’a permis de comprendre :

  • la différence entre droits Linux et droits Samba,
  • la gestion des utilisateurs et groupes,
  • la configuration d’un service réseau sous Linux,
  • la mise en place d’un partage multi‑plateforme,
  • la validation des droits via des tests Windows et Linux.

Cette activité m’a apporté une meilleure compréhension du fonctionnement d’un serveur de fichiers et de la gestion des permissions dans un environnement professionnel.
